# Бизнес-логика модулей выполняется на клиенте

Вся бизнес-логика расширений (хуки до и после операций, действия, повторы, перенос в архив) пишется на TypeScript и выполняется в браузере. Сервер — общий слой хранения без знаний о логике конкретных расширений (он знает лишь, какому расширению принадлежит тип, и скрывает данные отключённых расширений, см. ADR 0003): проверяет значения по метаданным типа, допустимые дочерние типы, владельца и роли, атомарно применяет набор изменений с проверкой значений «было» и пишет журнал. Так Undo/Redo и будущие пользовательские TS-скрипты строятся на одном механизме, а не на дублирующейся C#-логике.

## Considered Options

C#-хуки на сервере (как в Iris для серверной части). Отвергнуто: логика дублировалась бы с клиентскими скриптами, а побочные эффекты сервера усложняли бы клиентский Undo.

## Consequences

- Любой клиент в обход нашего кода может нарушить инварианты модуля; сервер защищает только общие правила платформы.
- Серверной автоматизации по расписанию нет: повторы достраиваются при входе в приложение, уведомления работают только при открытой вкладке.
- Если появится тяжёлая логика над большими данными или серверные задачи, её придётся запускать на сервере отдельным рантаймом TypeScript.
