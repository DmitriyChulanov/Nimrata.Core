# Единая дизайн-система: токены, UI-кит и реестр иконок

Весь интерфейс платформы и модулей строится из трёх частей: дизайн-токенов (значения оформления лежат только в `tokens.css`), UI-кита (`platform/ui/`, экспортируется через `@platform`) и реестра иконок на базе Lucide. Правила применения описаны в `docs/design-system.md` и не дублируют значения токенов. Модули импортируют из платформы только публичный `@platform`, типы ссылаются на иконки по имени из реестра, а запрет цветов и размеров вне токенов проверяет stylelint.

## Considered Options

- Только документ без общих компонентов и проверок. Отвергнуто: стиль расходится со временем, как уже случилось с эмодзи в манифесте трекера.
- Собственный набор иконок целиком. Отвергнуто: дорого поддерживать, а Lucide совпадает по стилю с текущими иконками (линия, штрих 1.5, `currentColor`).
- Пользовательские SVG-иконки в манифестах. Отвергнуто: риск недоверенной разметки и нарушение единого стиля; вернёмся к вопросу вместе с редактором расширений.
- Подключить готовую библиотеку компонентов (MUI и подобные). Отвергнуто: тянет чужой стиль и размер, а минималистичный стиль Nimrata проще выразить своим небольшим набором.

## Consequences

- Модуль не может оформить интерфейс произвольно: ему доступны только компоненты UI-кита, токены и иконки реестра. Нужный элемент добавляется в платформу.
- Иконка типа задаётся именем из реестра; эмодзи в манифестах не поддерживаются, неизвестное имя даёт запасную иконку и предупреждение в консоли.
- В реестр входит отобранное подмножество Lucide, поэтому для новой иконки нужно добавить её в реестр.
- Редактор расширений и пользовательские иконки потребуют пересмотра этого решения.
