# Подключение расширений хранится на сервере, данные отключённых расширений скрывает сервер

Какие расширения подключены, определяется личным состоянием пользователя в таблице на сервере (нет записи — действует `defaultEnabled` из манифеста). Сервер сам скрывает данные отключённых расширений: не отдаёт объекты их типов и записи журнала по ним и отклоняет запись в них. Данные при этом не удаляются и возвращаются при повторном подключении. Так по сети не ходят лишние данные, а состояние одинаково на всех устройствах пользователя.

## Considered Options

- Состояние подключения только в браузере (как Тема). Отвергнуто: «данные расширения» принадлежат пользователю, а не устройству, и на другом устройстве настройка терялась бы.
- Серверное состояние, скрытие фильтром на клиенте (`DataController`). Отвергнуто: сервер всё равно отдавал бы лишние данные, а скрытие зависело бы от каждого клиента.

## Consequences

- Сервер по-прежнему не знает логики расширений (ADR 0001), но знает принадлежность типа расширению и подключения пользователя; фильтры универсальны и не зависят от конкретных расширений.
- Подключение и отключение требуют перезагрузки данных с сервера, очистки истории Undo/Redo и сброса выделения на недоступные объекты.
- `ManifestValidator` запрещает вложенность типов разных расширений: фильтр работает по типу объекта, а не по поддереву.
- Журнал фильтруется по расширению типа записи, для этого `changeset_entries` хранит `type_id`; записи с неопределённым типом показываются всегда.
- Автосоздаваемые корни помечаются `singleton` в манифесте, и сервер отклоняет второй такой объект: скрытые корни не видны клиенту, и без этого он мог бы создать дубликат.
