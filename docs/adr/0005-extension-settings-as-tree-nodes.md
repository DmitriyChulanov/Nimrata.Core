# Настройки расширений — узлы дерева под общим платформенным корнем «Настройки»

Пользовательские настройки расширений хранятся обычными объектами дерева. Платформенный singleton-тип «Настройки» (`SettingsRoot`, без расширения-владельца, без `allowedChildren`) — единственный корень; в нём у каждого расширения свой узел настроек, чей тип и потомков объявляет манифест расширения. Узел и корень создаёт `ensureStart` расширения (`ensureSettingsNode`), удалять и переносить служебные узлы нельзя (`registerSettingsGuard`). Первый потребитель — «Типовые категории» Трекера задач: «Настройки» → «Трекер задач» → «Категории задач» → «Типовая категория».

## Considered Options

- Отдельная панель настроек с собственным хранилищем. Отвергнуто: нужна своя модель данных, API, Undo и скрытие при отключении расширения — всё это у объектов дерева уже есть.
- Корень настроек у каждого расширения (без общего). Отвергнуто: настройки разбросаны по дереву, общий вход «Настройки» удобнее и не требует знать расширения.

## Consequences

- Узлы настроек принадлежат типам расширения и скрываются сервером вместе с ним; корень «Настройки» остаётся (он платформенный) и пуст, пока нет подключённых расширений с настройками.
- Тип `SettingsRoot` добавляет серверная миграция `0024`; допустимость дочерних типов не ограничена, поэтому расширение само отвечает за состав своего узла.
- Действию можно задать варианты параметра по данным (`parameterValues` в `registerAction`, `getActionParameters`), чтобы диалог предлагал, например, типовые категории.
