# Дизайн-система

Единые правила оформления интерфейса платформы и модулей. Решение и его причины — в [ADR 0002](adr/0002-single-design-system.md), термины — в `GLOSSARY.md`.

Значения (цвета, размеры, отступы) задаёт только `nimrata.core.client/src/platform/theme/tokens.css`. Здесь они не повторяются: документ объясняет, **что означает токен и когда его применять**. Если значение нужно изменить, меняется токен, а не документ.

## Принципы

- **Спокойствие.** Интерфейс рабочего инструмента: плотный, тихий, без декоративных эффектов. Внимание привлекает только главное действие экрана.
- **Меньше линий.** Группы отделяются отступами и фоном, а не рамками. Граница нужна полю ввода, разделителю областей и карточке поверх содержимого.
- **Один акцент.** Акцентный цвет принадлежит главному действию, выбранному элементу и фокусу. На экране не бывает двух конкурирующих акцентных кнопок.
- **Один язык.** Одинаковые вещи выглядят одинаково на любом экране платформы и в любом модуле.
- **Обе темы с первого дня.** Любой элемент проверяется в светлой и тёмной теме.

## Токены

Все токены объявлены в `tokens.css`; светлая тема задаётся на `:root`, тёмная — атрибутом `data-theme="dark"` на `<html>`. Модули и компоненты ссылаются на токены через `var(--…)`.

### Правило

Цвета, отступы, радиусы, шрифты и тени записываются **только** токенами. Литералы (`#fff`, `rgb(...)`, `13px` для отступа) допустимы лишь в `tokens.css`. Нужного токена нет: сначала добавляется токен в обе темы, затем используется. Проверяет stylelint (`npm run lint:css`, входит в `npm run lint`): запрещены hex, `rgb()`/`hsl()` и именованные цвета, литералы размера и жирности шрифта, шрифт, радиус, тень, внешние и внутренние отступы вне `tokens.css`. Файлы, ещё не переведённые на токены, перечислены в `LEGACY_FILES` (`nimrata.core.client/stylelint.config.js`); новый файл туда не добавляется.

### Смысл токенов

| Группа | Токены | Применение |
| --- | --- | --- |
| Фон | `--bg`, `--bg-sidebar`, `--bg-hover`, `--bg-input` | `--bg` — основная поверхность; `--bg-sidebar` — боковые и служебные области; `--bg-hover` — наведение и выделение строки; `--bg-input` — поля ввода. |
| Границы | `--border`, `--border-strong`, `--border-control` | `--border` — тихие разделители и края кнопок; `--border-strong` — акцентирующие разделители областей; `--border-control` — края полей ввода, контраст не ниже 3:1 к фону. |
| Текст | `--text`, `--text-muted` | `--text` — содержимое; `--text-muted` — подписи, подсказки, неактивные значки. Важное не пишется приглушённым. |
| Акцент | `--accent`, `--accent-hover`, `--accent-contrast`, `--accent-bg` | Главное действие, выбранный элемент, фокус. `--accent-contrast` — цвет текста на акценте; `--accent-bg` — мягкая подложка выбранного. |
| Опасность | `--danger` | Ошибки и необратимые действия. Не используется для украшения. |
| Правила раскраски | `--rule-*` | Смысловые цвета объектов (например, приоритет). Подбираются под обе темы; ими раскрашивают значок или метку, а не крупные поверхности. |
| Размеры | `--space-*`, `--radius`, `--radius-lg` | Шкала отступов и скруглений. Отступы между соседними блоками одного уровня одинаковы. |
| Контролы | `--control-height` | Минимальная высота кнопок и полей: плотный, единый ритм форм. |
| Типографика | `--font`, `--mono`, `--text-*`, `--weight-*`, `--leading-*` | Шкала размеров: `--text-sm` — основной текст интерфейса, `--text-xs` — подписи и вторичное, `--text-md`/`--text-lg` — подзаголовки, `--text-xl` — заголовок экрана. Жирность только `--weight-medium` и `--weight-strong`; `--mono` — для кода и идентификаторов. |
| Иконки | `--icon-sm`, `--icon-md`, `--icon-lg`, `--icon-stroke` | Три размера и один штрих (см. «Иконки»). |
| Движение | `--transition` | Единая быстрая длительность для наведения и фокуса. При `prefers-reduced-motion` переходы отключаются. |
| Фокус | `--focus-ring` | Кольцо фокуса, общее для всех элементов. |
| Тень | `--shadow` | Только у элементов, всплывающих над содержимым: меню, диалоги. Карточка в потоке страницы теней не имеет. |
| Подложка | `--overlay` | Затемнение под модальным диалогом. |

## Состояния

Каждый интерактивный элемент определяет все состояния через токены:

- **Покой.** Основной вид.
- **Наведение.** Тихая подложка (`--bg-hover`); у акцентной кнопки — `--accent-hover`.
- **Фокус.** Видимое кольцо `:focus-visible` (`--focus-ring`). Убирать контур нельзя.
- **Нажатие и выбор.** Выбранный элемент отличается подложкой `--accent-bg`, а не только цветом текста.
- **Недоступность.** Приглушение; элемент остаётся читаемым.
- **Ошибка.** `--danger` для рамки и текста сообщения; сообщение читается скринридером (`role="alert"`).

## Доступность

- Контраст текста к фону не ниже WCAG AA (4,5:1 для обычного текста, 3:1 для крупного и значков) в **обеих** темах. Новая пара цветов проверяется до добавления токена.
- Все действия доступны с клавиатуры, порядок табуляции совпадает с визуальным.
- Значки без подписи получают `aria-label`; декоративные скрыты от вспомогательных технологий.
- Смысл не передаётся только цветом.

## Адаптивность

Интерфейс рассчитан на компьютер. Сужение до ширины планшета не ломает раскладку; мобильная вёрстка не поддерживается.

## Иконки

Иконки — одноцветные линейные, на основе Lucide; недостающие рисуются в том же стиле.

Иконка выводится компонентом `<Icon name="…" size="sm|md|lg" />` из `@platform`; размер и штрих задают токены, толщина линии не зависит от размера.

- **Подключение по имени.** Тип в манифесте задаёт иконку именем из реестра иконок (`"icon": "check-circle"`), не эмодзи и не разметкой. Неизвестное имя даёт запасную иконку и предупреждение в консоли.
- **Реестр** — отобранное подмножество библиотеки, хранится в `nimrata.core.client/src/platform/icons/`. Список имён ведётся там и в документе не дублируется. Нужна новая иконка: добавьте её в реестр, а не рисуйте на месте.
- **Размеры.** Три: малый (`--icon-sm`), основной (`--icon-md`, по умолчанию) и крупный (`--icon-lg`).
- **Штрих.** Один для всех иконок (`--icon-stroke`), скруглённые концы и соединения.
- **Цвет.** Наследуется от текста (`currentColor`): иконка принимает цвет контекста, в том числе смысловой цвет узла (`--rule-*`). Приглушённую иконку получают, задав контексту `--text-muted`. Акцент допустим только у иконки главного действия или выбранного элемента.
- **Пользовательские SVG** не поддерживаются.

## Компоненты (UI-кит)

Единый набор универсальных компонентов лежит в `nimrata.core.client/src/platform/ui/` и экспортируется через `@platform`. Состав:

| Компонент | Назначение |
| --- | --- |
| `Button` | Кнопка с видами `primary` (главное действие области), `secondary` (по умолчанию), `ghost`, `danger`; тип по умолчанию `button`; необязательная иконка. |
| `IconButton` | Квадратная кнопка с одной иконкой; подпись `label` обязательна (доступное имя и подсказка). |
| `TextField`, `TextArea` | Подписанное поле с подсказкой `hint` и ошибкой `error`; связи `aria-describedby` и `aria-invalid` ставятся сами. |
| `Select` | Подписанный выпадающий список по массиву `options`; пустой вариант — через `placeholder`. |
| `Dialog` | Модальный диалог: заголовок, содержимое, `actions`; удерживает фокус, закрывается по Esc, возвращает фокус; роль `dialog` или `alertdialog` для подтверждений. |
| `Menu` | Выпадающее меню действий: кнопка, пункты с иконкой, подсказкой клавиш, видами недоступен и опасный; стрелки, Esc, клик снаружи. |
| `Badge` | Короткий статус или счётчик; тоны `neutral`, `accent`, `danger`. |

- Экран собирается из компонентов UI-кита; собственные кнопки, поля и диалоги не пишутся.
- Компонент использует только токены и не содержит значений оформления.
- Компонент не знает о модулях: платформа не импортирует из модулей.
- Нужного элемента нет: он добавляется в UI-кит с тестом, а не оформляется локально.
- Кнопка: одно главное действие на область (заметный вариант), остальные — спокойные; опасное действие оформляется токеном опасности.

## Модули

Модуль подчиняется тем же правилам, что и платформа.

- Из платформы импортируется только публичный `@platform`, без глубоких путей.
- Собственные стили допустимы, но используют только токены и проходят ту же проверку.
- Иконки типов, действий и вкладок — только из реестра по имени.

## Добавление и изменение

1. Новая потребность: проверьте UI-кит, токены и реестр иконок; чаще всего подходит имеющееся.
2. Новый токен: добавить в обе темы, проверить контраст AA, описать смысл в таблице выше.
3. Новый компонент: добавить в `platform/ui/`, покрыть тестом, проверить обе темы и клавиатуру.
4. Новая иконка: добавить в реестр, соблюдая размеры и штрих.

## План внедрения

Текущее состояние: токены, реестр иконок, UI-кит и stylelint готовы; остаётся перевести на них существующие экраны, после чего `LEGACY_FILES` будет пуст.

Правила вводятся поэтапно: токены и состояния, реестр иконок и миграция манифеста трекера, UI-кит, stylelint с временными исключениями, затем поэкранный перевод существующего интерфейса. Пока экран не переведён, он может нарушать правила; новый код нарушать их не должен.
