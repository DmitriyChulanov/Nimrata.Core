# Журнал изменений

## Не выпущено

- Трекер задач: действие «Отложить» у категории (`postpone` у `Category`, параметр «Дата»): переносит все незавершённые задачи категории и вложенных категорий в выбранный день с сохранением цепочки категорий тем же переносом, что и у одной задачи (`relocate` в `completion.ts`); опустевшие категории удаляются, пустая категория и перенос на ту же дату ничего не меняют, всё одним набором изменений (одна отмена).

- Исправления код-ревью расширений: ошибка переключения подключения показывается только у карточки в Редакторе расширений (глобальный `role="alert"` `ExtensionsProvider` остаётся для ошибки каталога и запуска); JSDoc `ExtensionsProvider`, `ExtensionsEditor`, `NoExtensionsNotice`, `useExtensions`, `registerExtensionsEditor`, `notesExtension`, `ensureStart` и `App` приведён к правилам навыков.

- Редактор расширений: вкладка «Расширения» (одна копия) и пункт «Вид → Расширения» (`registerExtensionsEditor`, `platform/extensionCatalog/`). Карточка расширения: иконка из реестра (неизвестное имя даёт запасную), название, описание, переключатель «Подключено» и пояснение «Данные скрываются и вернутся при повторном подключении»; подтверждения нет; во время переключения карточки заблокированы, отказ сервера показывается у карточки. Пока отключены все расширения, вместо дерева показывается подсказка открыть «Вид → Расширения» (`NoExtensionsNotice`).
- UI-кит: компонент `Switch` (роль `switch`, токены `--switch-width`/`--switch-height`, видимый фокус, обе темы) с тестами.
- Повторная загрузка данных при переключении расширения больше не заменяет рабочую область индикатором «Загрузка…»: вкладки не пересоздаются.

- Подключение и отключение расширений без перезагрузки страницы: `ExtensionsProvider`/`useExtensions` (`@platform`, `platform/extensionCatalog/`) загружают каталог `GET /api/extensions`, регистрируют только подключённые расширения реестра и рисуют их компоненты-привязки (пока «Трекер задач» отключён, нет его хуков, действий, повторов и уведомлений); `setConnected(id, connected)` (`PUT /api/extensions/{id}/connection`) снимает или регистрирует `register`, перезагружает данные (Undo/Redo очищаются), сбрасывает выделение недоступного объекта и вызывает `ensureStart` включаемого расширения. `App` расширений не перечисляет и берёт их из `extensionRegistry`.
- `ensureStart` расширений идемпотентен и устойчив к гонке (`ensureCreated`): отказ сервера `singleton_exists` считается «уже есть» (данные перезагружаются), прочий 409 без `code` перезагружает данные и повторяет попытку один раз; отказ запуска одного расширения не блокирует второе.
- `ApiError.code` (машинный код отказа из тела ответа) и поля `status`/`code` в отказе `ChangeResult`.
- `fakeApi` умеет каталог расширений и подключения (`createFakeApi(types, objects, { extensions })`): скрывает объекты отключённых расширений, сохраняет принятые наборы, отказывает `extension_disabled` и `singleton_exists`; `rejectNext(status, message, code?)`. Тесты переключения, гонки и `App` переведены на него.

- Манифесты `tasks` и `notes` повышены до версии 13: метаданные расширения (`name`, `description`, `icon`, `defaultEnabled`) и признак `singleton` у `TasksRoot`, `CurrentTasksRoot`, `CompletedTasksRoot`, `SelectTodayMechanism`, `NotesRoot`; в `TypeDefinition` добавлено необязательное поле `singleton`. Использует серверная часть подключений расширений.

- Разделение Трекера на два независимых расширения: `extensions/tasks` («Трекер задач», алиас `@tasks`, манифест v12) и `extensions/notes` («Трекер заметок», алиас `@notes`, манифест v12); алиас `@tracker` удалён. ESLint запрещает расширениям импортировать друг друга. Общее вынесено в `@platform`: `safeUrl`, действия внешней и внутренней ссылки, `RevealBinding`/`createRevealBridge`, `createNode`, `orThrow`, `cancelIfFailed`.
- Клиентский дескриптор расширения `ExtensionDescriptor` (`register(data, options)` возвращает отписку, идемпотентный `ensureStart`, необязательные компоненты-привязки, например уведомления Трекера задач) и реестр `extensionRegistry` в платформе; `App` перебирает расширения из реестра и конкретных не знает (встроенные перечислены в `src/extensions/index.ts`). Первый вход создаёт стартовую структуру каждого расширения отдельным набором изменений.
- Переименование «модуль» → «расширение» без смены поведения: `src/modules/` → `src/extensions/` (алиас `@tracker` прежний), поля типа `module`/`moduleVersion` → `extension`/`extensionVersion`, ключ `extension` в манифесте Трекера, lint-правило `no-restricted-imports` и конфигурации Vite/Vitest/tsconfig обновлены.
- Документация дизайн-системы `docs/design-system.md` (принципы, смысл токенов, состояния, иконки, UI-кит, правила для модулей) и ADR 0002.
- Токены: шкала типографики, высота контролов, размеры иконок, переход, кольцо фокуса, `--border-control` (контраст границ полей не ниже 3:1); базовые стили на токенах, уважают `prefers-reduced-motion`.
- Иконки: реестр на Lucide (`platform/icons/registry.ts`) и компонент `Icon` вместо рукописных `ChevronIcon`, `CloseIcon`, `LogoutIcon`; в манифесте Трекера эмодзи заменены именами из реестра; дерево, вкладки и выбор ссылки рисуют иконку типа через `Icon`, неизвестное имя даёт запасную иконку и предупреждение.
- UI-кит `platform/ui/`: `Button`, `IconButton`, `TextField`, `TextArea`, `Select`, `Dialog`, `Menu`, `Badge` (экспорт через `@platform`) с тестами; токен `--overlay` для подложки диалога.
- stylelint (`stylelint.config.js`, `npm run lint:css`, входит в `npm run lint`): запрет цветов, шрифтов, радиусов, теней и отступов-литералов вне `tokens.css`; не переведённые экраны временно перечислены в `LEGACY_FILES`.
- Экраны входа, смены пароля, диалог действий, подтверждение удаления, вкладки, таблица свойств с выбором ссылки, журнал, пользователи, автоматизация и шапка переведены на UI-кит (добавлен `Checkbox`); `LEGACY_FILES` удалён, исключений stylelint нет.
- Манифест Трекера v10: версия поднята, чтобы сервер обновил в БД типы с эмодзи на имена иконок из реестра (без этого дерево показывало запасные иконки); иконки «День» и «Выделить текущий день» заменены на `calendar-1` и `crosshair`.
- Цвет иконок типов: поле `iconColor` в определении типа (имя палитры `--rule-*`), `Icon` принимает `tone`, компонент `TypeIcon` рисует иконку узла в дереве и в выборе ссылки; цветовое правило строки сильнее цвета иконки. В манифесте Трекера цвета заданы по семействам типов, версия манифеста 11.
- Каркас клиента: области `platform/` и `modules/tracker/` с алиасами `@platform` и `@tracker`, ESLint-правило запрета импорта модулей из платформы.
- API-клиент `createApiClient` (обёртка над `fetch`: базовый адрес `/api`, заголовки, `ApiError`) с тестами.
- Прокси Vite: единый префикс `/api` вместо `/weatherforecast`.
- Вход: экран входа `LoginScreen`, `AuthProvider`/`useAuth`/`useApi`, `createAuthSession`; access-токен хранится только в памяти, сессия восстанавливается через refresh-cookie после обновления страницы, выход отзывает refresh на сервере.
- API-клиент: опция `onUnauthorized` — при 401 один раз обновляет токен и повторяет запрос.
- Манифест Трекера v0 (`src/modules/tracker/manifest.json`: корневые группы, «Заметка», «Группа заметок»); сервер читает тот же файл.
- Типы: `TypesProvider`/`useTypes` загружают `GET /api/types` после входа и хранят типы в платформе; TS-типы `TypeDefinition` и связанные.
- Демо-экран с прогнозом погоды заменён заглушкой приложения.
- `vite.config.ts`: сертификат `dotnet dev-certs` создаётся и читается только для dev-сервера (`vite`), поэтому `npm run build` работает без .NET (например, в Docker).
- Модель данных: `createDataController` (`platform/data/`) загружает типы и объекты, даёт синхронное чтение (`getObject`, `getChildren`, `orderAt`) и применяет создание, изменение свойства, перемещение и удаление поддерева одним набором изменений (UUIDv7 на клиенте); при отказе сервера откатывает локальную модель и выставляет причину, при 409 — состояние «нужна перезагрузка» (`load()` заменяет модель); подписка `subscribe`/`getSnapshot` для UI; тесты на поддельном API в памяти.
- API-клиент: причина отказа читается и из поля `error` (ответы `POST /api/changesets`).
- Раскладка и дерево: `Workspace` (три панели — дерево, вкладки, свойства; ширина боковых панелей меняется перетаскиванием границ или стрелками), универсальное `Tree` в `platform/` (узлы по `DataController`: сортировка по порядку и названию, иконка типа `icon`, скрытие `hiddenInTree`, раскрытие/сворачивание, виртуализация строк, контекстное меню «Создать» для допустимых неабстрактных дочерних типов и «Удалить» с подтверждением — через наборы изменений), `DataProvider`/`useData` и `SelectionProvider`/`useSelection` (выделенный объект доступен всем панелям); `TypeDefinition.icon`. Главный экран приложения собран из этих частей, панель свойств пока показывает выделенный объект.
- Дерево: перенос узлов перетаскиванием (середина строки — стать потомком, верхняя/нижняя четверть — встать перед/после соседа) и с клавиатуры (Alt+↑/↓ — порядок, Alt+→ — внутрь предыдущего соседа, Alt+← — на уровень выше); недопустимые цели (тип не разрешён родителем через `allowedChildren`, сам узел, его потомок) подсвечиваются через `aria-disabled` и не принимают drop; перенос — один набор изменений, при отказе сервера дерево откатывается и показывается сообщение. Логика допустимости — `planMove` в `platform/tree/`.
- Цветовые правила в дереве: узел красится цветом первого подходящего правила `colorRules` типа (логика — `platform/tree/colorRules.ts`); цвета палитры (`red`, `orange`, `yellow`, `green`, `blue`, `purple`, `gray`) имеют оттенки для светлой и тёмной темы (`ruleColors.css`), прочие значения CSS применяются как есть; цвет обновляется при изменении свойства без перезагрузки.
- `DataController`: индекс потомков по родителю (быстрый `getChildren` для больших деревьев).
- Главное меню, вкладки и реестры (`platform/tabs/`): реестры `tabRegistry` (идентификатор, заголовок, компонент, одна или несколько копий) и `menuRegistry` (путь, обработчик, необязательная роль) для регистрации из TypeScript; `MainMenu` показывает только пункты, доступные роли; `TabContainer` и `TabsProvider` (открытие, переключение, закрытие; вид с одной копией переключает на уже открытую вкладку). Открытые вкладки, активная вкладка и ширины панелей запоминаются в `localStorage` отдельно для каждого пользователя (`nimrata.layout.<id>`); недоступное или повреждённое хранилище игнорируется. `useCurrentUser` читает `GET /api/auth/me` (роль `admin`/`member`); `Workspace` получил `onWidthsChange`.
- Таблица свойств: `PropertyGrid` (`platform/properties/`) строится по описанию типа выделенного объекта (категории в порядке описания, «Прочее» — для свойств без категории); редакторы для строки, многострочного текста, целого, логического, даты (`ГГГГ-ММ-ДД`), времени (`ЧЧ:мм`) и перечисления; недопустимый ввод не отправляется, а показывается причиной; свойства «только чтение» заблокированы; ссылочные свойства — текстом только для чтения; каждая правка — набор изменений, при отказе значение откатывается и показывается причина. Панель свойств главного экрана использует `PropertyGrid`.
- Ссылочные свойства: редактор `ReferenceEditor` в таблице свойств показывает название цели (удалённая цель — «Недоступный объект»), открывает диалог с деревом для выбора объекта (объекты, не подходящие под `targetTypes`, отключены; применяется набором изменений), очищает ссылку и по кнопке «→» переходит к цели: `SelectionProvider.reveal` выделяет узел, `Tree` раскрывает родителей и прокручивает к строке.
- `DataController.create`: подставляет значения `default` из определения свойств типа (явно заданные значения приоритетнее).
- Админка пользователей: вкладка «Пользователи» (`platform/users/UsersTab`) — список, создание учётной записи (e-mail, имя, пароль, роль), смена роли, отключение и включение; причина отказа сервера (например, «последний администратор») показывается над формой. Регистрируется `registerUsersAdmin` (вкладка и пункт «Администрирование → Пользователи» с ролью `admin`, участник пункт не видит).
- Undo/Redo: `DataController.undo()/redo()/canUndo()/canRedo()` — стек действий в памяти вкладки (логика в `platform/data/undoHistory.ts`); обратный набор (изменение свойства, перемещение, создание, удаление с пересозданием поддерева по снимку) строится на клиенте и применяется без хуков; новый набор очищает стек повторов, перезагрузка данных очищает оба стека; при отказе сервера (в т.ч. конфликт «было/стало», 409) стек и модель не меняются, показывается сообщение. `UndoControls` регистрирует пункты «Правка → Отменить / Повторить» в реестре меню и горячие клавиши Ctrl/Cmd+Z, Ctrl+Y, Ctrl/Cmd+Shift+Z (в полях ввода не срабатывают); `MenuItem` получил `enabled`, `shortcut`, `subscribe`, `MenuRegistry.register` возвращает отписку, `MainMenu` показывает недоступные пункты отключёнными.
- Хуки, действия и диалог параметров: `DataController.registerHook(тип | '*', операция, 'before' | 'after', обработчик)` — хук «до» отменяет операцию (`{ cancel: сообщение }`), хуки «до» и «после» дополняют тот же набор изменений через `ctx.tx`; отказ или исключение любой вложенной операции отменяет весь набор, глубина вложенности хуков ограничена; `perform(fn)` — произвольная последовательность операций одним набором; необязательный аргумент `{ hooks: false }` у `create`/`setProperty`/`move`/`remove`/`perform`/`runAction` отключает хуки (повторы, Undo); `registerAction(тип, действие, обработчик)`, `getActions(объект, placement)` (действие без обработчика не возвращается) и `runAction(объект, действие, параметры)` с проверкой обязательных параметров; `PropertyDefinition.required`. UI: кнопки действий `propertyGrid` над таблицей свойств, пункты `contextMenu` в меню дерева, `ActionDialog` (поля по восьми видам параметров, проверка формата и обязательности) и `useActionLauncher`.
- Трекер: стартовая структура и «Заметки» (`modules/tracker/tracker.ts`). Манифест v2: у «Заметки» свойства «Название» (`title`), вычисляемое «Имя» (`name`, только чтение), «Комментарий», «Приоритет», «Статус» (без значения по умолчанию; «Завершена»), «Внешняя ссылка»; параметры «Название» у действий создания. `ensureStartStructure` при входе создаёт недостающие корни («Задачи» с «Текущие задачи» и «Завершённые задачи», «Заметки») одним набором, повторный вход дублей не создаёт; `registerTracker` подключает действия «Создать заметку»/«Создать группу заметок» (с вложенностью), хуки «после» пересчёта имени «[Статус] Название» (в том же наборе, что и правка) и «Перейти по внешней ссылке» (новая вкладка с `noopener`, только http/https). Платформа: `registerAction(тип, действие, обработчик, { available })` — условие доступности действия по объекту (используется в `getActions` и `runAction`).
- Вкладка «Автоматизация» (`platform/automation/`): `AutomationTab` показывает объекты типов с отметкой `automation` (в том числе скрытые в дереве через `hiddenInTree`) и кнопки их действий с размещением `automation`; клик запускает действие через `useActionLauncher` (диалог параметров, ошибки показываются), список обновляется при создании и удалении механизмов. `registerAutomation` регистрирует вид вкладки и пункт «Вид → Автоматизация»; вызывается в `App.tsx`.
- Трекер: Задачи (`modules/tracker/tasks.ts`). Манифест v5 (v3 — задачи, v4 — быстрый доступ): типы «Год», «Месяц», «День», «День-выходной» (иконка 🏖), «Категория», «Задача» (название, вычисляемое имя, время, комментарий, приоритет, статус, «Уведомить за (мин)», внешняя и внутренняя ссылки, вид повтора, скрытый идентификатор повтора), цветовые правила приоритета и статуса задачи. Действие «Создать задачу» (на «Текущих задачах», месяце, дне и категории; параметры: название, дата, категория): одним набором находит или создаёт месяц и день внутри «Текущих задач» (суббота и воскресенье — «День-выходной»), затем категорию по названию (повторное название находит существующую, на категории создаётся вложенная); без даты берётся день, на котором запущено действие, а на «Текущих задачах» и месяце — сегодня. Имена вычисляются: месяц «MMMM, yyyy», день «dd.MM.yyyy, dddd», задача «HH:mm — Название» (пересчитывается при правке названия и времени). Дата задачи не хранится: `taskDate` берёт её у дня-родителя. Сортировка: месяцы и дни получают `order` по дате, задачи дня — по времени (без времени первыми, категории перед ними; пересчёт при смене времени). Действия «Перейти по внешней ссылке» (http/https, новая вкладка) и «Перейти по внутренней ссылке» (`registerTracker(data, { reveal })`; в приложении `reveal` подключается через `RevealBinding`/`createRevealBridge`). Платформа: `PropertyDefinition.hidden` скрывает служебное свойство в таблице свойств. Пока категорию в диалоге нужно вводить текстом (выбор существующей из списка — отдельным шагом).
- Трекер: быстрый доступ (`modules/tracker/quickAccess.ts`). Манифест v4: тип «Быстрый доступ» (`QuickAccessEntry`, механизм `automation`, `hiddenInTree`; свойства «Название» и ссылка «Цель» на заметку или группу) и действия «Добавить»/«Убрать» у «Заметки» и «Группы заметок» (таблица свойств и контекстное меню). «Добавить» дубля не создаёт и доступно, пока записи нет; «Убрать» удаляет все записи цели. Манифест v6 (после слияния с «Выделить текущий день» — v8): у «Задачи» действия «Завершить» и «Отложить» (параметр «Дата», обязательный; таблица свойств и контекстное меню; недоступны завершённой задаче). «Завершить» ставит статус «Завершена» и переносит задачу в «Завершённые задачи» в день с той же датой (год, месяц и день создаются по требованию), «Отложить» переносит в день выбранной даты в «Текущих задачах»; цепочка категорий воссоздаётся по названиям, порядок задачи по времени сохраняется; та же дата — без изменений. После переноса и после удаления задачи пустая цепочка категорий удаляется вверх до дня (день не трогается). Всё — один набор изменений, Undo возвращает задачу и категории на место.
- Итог пилота: каркас клиента (`platform/`, `modules/tracker/`), API-клиент, экран входа и сессия на refresh-cookie; клиент собирается в `dist` и раздаётся сервером из `wwwroot` (единый деплой). Остальное (панели, дерево, таблица свойств, Трекер) — по соответствующим тикетам.
