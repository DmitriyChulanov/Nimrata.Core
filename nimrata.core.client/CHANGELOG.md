# Журнал изменений

## Не выпущено

- Каркас клиента: области `platform/` и `modules/tracker/` с алиасами `@platform` и `@tracker`, ESLint-правило запрета импорта модулей из платформы.
- API-клиент `createApiClient` (обёртка над `fetch`: базовый адрес `/api`, заголовки, `ApiError`) с тестами.
- Прокси Vite: единый префикс `/api` вместо `/weatherforecast`.
- Вход: экран входа `LoginScreen`, `AuthProvider`/`useAuth`/`useApi`, `createAuthSession`; access-токен хранится только в памяти, сессия восстанавливается через refresh-cookie после обновления страницы, выход отзывает refresh на сервере.
- API-клиент: опция `onUnauthorized` — при 401 один раз обновляет токен и повторяет запрос.
- Манифест Трекера v0 (`src/modules/tracker/manifest.json`: корневые группы, «Заметка», «Группа заметок»); сервер читает тот же файл.
- Типы: `TypesProvider`/`useTypes` загружают `GET /api/types` после входа и хранят типы в платформе; TS-типы `TypeDefinition` и связанные.
- Демо-экран с прогнозом погоды заменён заглушкой приложения.
- `vite.config.ts`: сертификат `dotnet dev-certs` создаётся и читается только для dev-сервера (`vite`), поэтому `npm run build` работает без .NET (например, в Docker).
- Модель данных: `createDataController` (`platform/data/`) загружает типы и объекты, даёт синхронное чтение (`getObject`, `getChildren`, `orderAt`) и применяет создание, изменение свойства, перемещение и удаление поддерева одним набором изменений (UUIDv7 на клиенте); при отказе сервера откатывает локальную модель и выставляет причину, при 409 — состояние «нужна перезагрузка» (`load()` заменяет модель); подписка `subscribe`/`getSnapshot` для UI; тесты на поддельном API в памяти.
- API-клиент: причина отказа читается и из поля `error` (ответы `POST /api/changesets`).
- Раскладка и дерево: `Workspace` (три панели — дерево, вкладки, свойства; ширина боковых панелей меняется перетаскиванием границ или стрелками), универсальное `Tree` в `platform/` (узлы по `DataController`: сортировка по порядку и названию, иконка типа `icon`, скрытие `hiddenInTree`, раскрытие/сворачивание, виртуализация строк, контекстное меню «Создать» для допустимых неабстрактных дочерних типов и «Удалить» с подтверждением — через наборы изменений), `DataProvider`/`useData` и `SelectionProvider`/`useSelection` (выделенный объект доступен всем панелям); `TypeDefinition.icon`. Главный экран приложения собран из этих частей, панель свойств пока показывает выделенный объект.
- `DataController`: индекс потомков по родителю (быстрый `getChildren` для больших деревьев).
- Главное меню, вкладки и реестры (`platform/tabs/`): реестры `tabRegistry` (идентификатор, заголовок, компонент, одна или несколько копий) и `menuRegistry` (путь, обработчик, необязательная роль) для регистрации из TypeScript; `MainMenu` показывает только пункты, доступные роли; `TabContainer` и `TabsProvider` (открытие, переключение, закрытие; вид с одной копией переключает на уже открытую вкладку). Открытые вкладки, активная вкладка и ширины панелей запоминаются в `localStorage` отдельно для каждого пользователя (`nimrata.layout.<id>`); недоступное или повреждённое хранилище игнорируется. `useCurrentUser` читает `GET /api/auth/me` (роль `admin`/`member`); `Workspace` получил `onWidthsChange`.
- Итог пилота: каркас клиента (`platform/`, `modules/tracker/`), API-клиент, экран входа и сессия на refresh-cookie; клиент собирается в `dist` и раздаётся сервером из `wwwroot` (единый деплой). Остальное (панели, дерево, таблица свойств, Трекер) — по соответствующим тикетам.
