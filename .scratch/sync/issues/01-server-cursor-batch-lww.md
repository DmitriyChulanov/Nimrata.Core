# 01: Сервер — курсор, пакетная запись, LWW, догон

**What to build:** Сервер присваивает наборам монотонный `seq`, принимает пакет наборов с клиентскими `id` и отбрасывает повторы. Конфликты решаются по LWW со строгими структурными инвариантами. Сервер отдаёт изменения с курсора и согласованную полную загрузку.

**Blocked by:** —

**Status:** ready-for-agent

- [ ] Миграция: `changesets.seq bigint generated always as identity` (уникальный индекс)
- [ ] `POST /api/changesets` → `{ changesets: [{ id, operations }] }`, ответ 200 со списком `{ id, status: applied | duplicate | rejected, seq?, code?, detail? }`; каждый набор — своя транзакция; 4xx только на формат и авторизацию
- [ ] Идемпотентность: повтор известного `id` → `duplicate` с прежним `seq`, без повторного применения
- [ ] `pg_advisory_xact_lock` по пользователю на время применения набора; тест: порядок `seq` совпадает с порядком фиксации
- [ ] LWW: `update` и `move` (`parent`, `number`) не сверяют «было», журнал пишет фактическое старое значение; структурные инварианты (существование, `allowedChildren`, цикл, singleton, включённое расширение, дети удаляемого, дубликат `create`) остаются отказом
- [ ] Контракт `contracts/changeset`: пересмотреть категорию `was` (README, сценарии); серверные и клиентские контрактные тесты зелёные (`fakeApi` следует новому контракту)
- [ ] `GET /api/changes?since=N` → `{ toSeq, changesetIds, upserts, deletes }` либо `{ resync: true }` при превышении порога; фильтр видимости как в `GET objects`
- [ ] Полная загрузка в `repeatable read` возвращает `seq` снимка (форма ответа согласуется с клиентом в 02)
- [ ] Секция настроек `Sync:` (`ResyncThreshold`, `PushWindow`) и `docs/configuration.md`
- [ ] Клиентский `DataController` минимально переведён на новый формат запроса и ответа (без двух слоёв — это 02), чтобы приложение работало
- [ ] Тесты сервера (HTTP + Testcontainers), `dotnet test`, `npm test`; запись в `CHANGELOG.md` сервера
