# 02: Клиент — двухслойное хранилище и адресные подписки

**What to build:** Хранилище клиента разделяет подтверждённое состояние и очередь неподтверждённых наборов и умеет rebase. Компоненты подписываются адресно и перерисовываются только при изменении своих данных.

**Blocked by:** 01

**Status:** resolved

- [x] Подтверждённый слой + очередь; видимая модель = подтверждённое состояние с наложенной очередью; курсор `seq`
- [x] `applyRemote({ toSeq, upserts, deletes, changesetIds })`: применение к подтверждённому слою, переналожение очереди без хуков, распознавание своих наборов по `id`
- [x] Подтверждение и отказ набора: перенос в подтверждённый слой; при отказе — откат и каскад зависимых наборов, одно сводное уведомление; структурная проверка общим кодом контракта (как в `fakeApi`)
- [x] Упразднить `needsReload` и глобальную блокировку записи (`DataController`, `ensureStart`)
- [x] Undo: перед отменой сверка текущего значения со своим; при несовпадении — отказ записи с уведомлением; стек только во вкладке
- [x] Вычисление множества изменённых id и родителей на каждое применение; уведомление только затронутых подписчиков
- [x] Хуки `useObject(id)`, `useChildren(parentId)`, `useQuery(selector, deps)` в `@platform`; тесты на отсутствие лишних перерисовок
- [x] Дерево: мемоизированная строка на объект; PropertyGrid: подписка на выделенные объекты; остальные потребители `useData()` пересмотрены
- [x] Тесты (Vitest, `createFakeApi`), `npm test`, `npm run lint`; запись в `CHANGELOG.md` клиента

## Comments

- Хранилище — `platform/data/dataStore.ts` (`createDataStore`), правила контракта вынесены в `platform/data/changesetRules.ts` (`checkChangeset`), их используют и `fakeApi`, и переналожение очереди.
- Сеть пока минимальна: `createDirectTransport(api)` — один набор на запрос, запросы по одному, ошибка запроса = отказ набора (откат). SyncEngine (03) подключается через `DataControllerOptions.transport` и `controller.sync` (`SyncPort`: `getSeq`, `pending`, `subscribePending`, `confirm`, `reject`, `applyRemote`, `reset`).
- Таблица свойств подписана не только на выделенные объекты, но и на их название и доступность общих действий (через `useQuery`): иначе действия, зависящие от других объектов (быстрый доступ заметок), показывались бы устаревшими.
- `useData()` оставлен в «Командах», «Журнале» и диалоге действия: там нужна вся модель.
