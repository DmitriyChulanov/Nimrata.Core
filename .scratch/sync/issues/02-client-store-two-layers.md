# 02: Клиент — двухслойное хранилище и адресные подписки

**What to build:** Хранилище клиента разделяет подтверждённое состояние и очередь неподтверждённых наборов и умеет rebase. Компоненты подписываются адресно и перерисовываются только при изменении своих данных.

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] Подтверждённый слой + очередь; видимая модель = подтверждённое состояние с наложенной очередью; курсор `seq`
- [ ] `applyRemote({ toSeq, upserts, deletes, changesetIds })`: применение к подтверждённому слою, переналожение очереди без хуков, распознавание своих наборов по `id`
- [ ] Подтверждение и отказ набора: перенос в подтверждённый слой; при отказе — откат и каскад зависимых наборов, одно сводное уведомление; структурная проверка общим кодом контракта (как в `fakeApi`)
- [ ] Упразднить `needsReload` и глобальную блокировку записи (`DataController`, `ensureStart`)
- [ ] Undo: перед отменой сверка текущего значения со своим; при несовпадении — отказ записи с уведомлением; стек только во вкладке
- [ ] Вычисление множества изменённых id и родителей на каждое применение; уведомление только затронутых подписчиков
- [ ] Хуки `useObject(id)`, `useChildren(parentId)`, `useQuery(selector, deps)` в `@platform`; тесты на отсутствие лишних перерисовок
- [ ] Дерево: мемоизированная строка на объект; PropertyGrid: подписка на выделенные объекты; остальные потребители `useData()` пересмотрены
- [ ] Тесты (Vitest, `createFakeApi`), `npm test`, `npm run lint`; запись в `CHANGELOG.md` клиента
