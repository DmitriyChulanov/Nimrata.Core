# 05: Офлайн — снимок и очереди в IndexedDB

**What to build:** Снимок данных, курсор и очереди вкладок хранятся в IndexedDB. Правки переживают перезагрузку и отсутствие сети, очереди закрытых вкладок подхватываются.

**Blocked by:** 03, 04

**Status:** resolved

- [x] Тонкая обёртка над IndexedDB; база по `userId`: снимок объектов и типов, курсор, очереди по `tabId`
- [x] Снимок пишется, только если `seq` больше сохранённого
- [x] Старт: показать снимок из кэша, затем догон; без сети — работа на кэше
- [x] Web Locks: lock вкладки; очередь вкладки с отпущенным lock подхватывается
- [x] Logout: предупреждение при непустой очереди, затем удаление базы. Если вход истёк в офлайне — работа локально, после входа тем же пользователем очередь отправляется
- [x] Тесты с `fake-indexeddb`; `npm test`, `npm run lint`; `CHANGELOG.md` клиента

## Comments

- Модули: `platform/offline/offlineDb.ts` (обёртка: `meta` — снимок и каталог, `queues` — по `tabId`; снимок и очередь вкладки пишутся одной транзакцией), `tabLocks.ts` (Web Locks / в памяти), `offlineSync.ts` (`createOfflineSync`: lock вкладки, старт из кэша, подхват очередей при старте и раз в 10 с, сохранение через 100 мс и на `pagehide`). `tabId` — новый на каждую загрузку страницы, поэтому перезагрузка = «закрытая вкладка», её очередь подхватывается при старте.
- Итог действия теперь локальный (не ждёт сервера); поздний отказ — сводное уведомление (`DataController.onNotice`, показывает `UndoControls`). `OperationOptions.confirmed: true` ждёт сервер — так `ensureStart` расширений сохраняет обработку `singleton_exists`. Тесты, смотревшие на `api.changesets` и отказы, ждут через `whenSynced(data)` или `confirmed: true`.
- Восстановленные наборы (`DataStore.restoreQueue`) не отбрасываются локально, если неприменимы к подтверждённому слою (могли уже примениться на сервере), — ждут `duplicate`/отказа. `confirm` с `seq` ≤ курсора не применяет операции повторно.
- Вход: сбой сети при обновлении токена → `AuthStatus` `'offline'` (не выход); последний пользователь запоминается в `localStorage` (`nimrata.currentUser`, только id и роль). Каталог расширений кэшируется в той же базе.
- Ограничение: снимок пишется только при росте `seq`; смена типов без нового набора (подключение расширения) попадёт в кэш со следующим набором.
