# 04: Push по SignalR и догон при переподключении

**What to build:** Сервер рассылает изменения подключённым клиентам пользователя пакетами раз в 100 мс. Клиент применяет их, а после разрыва догоняет с курсора.

**Blocked by:** 01, 03

**Status:** ready-for-agent

- [ ] Хаб `/api/sync`, группа `user:{id}`; JWT из query `access_token` только для пути хаба
- [ ] `IChangeNotifier`: пометка «грязного» пользователя после фиксации; диспетчер раз в 100 мс читает журнал из БД после последнего отправленного `seq` и рассылает сообщение в формате догона; медленному клиенту — `resync`
- [ ] Подключение и отключение расширения рассылается как `resync`
- [ ] Прокси Vite: `ws: true` в правиле `^/api`
- [ ] Клиент (`@microsoft/signalr`): подключение в `SyncEngine`, переподключение (в том числе после обновления токена), догон `GET /api/changes?since=N` после соединения, `resync` → полная загрузка с переналожением очереди
- [ ] Вкладка «Журнал» перечитывает первую страницу при сдвиге курсора
- [ ] Тесты сервера с `Microsoft.AspNetCore.SignalR.Client`: две «вкладки» одного пользователя, чужой пользователь ничего не получает, группировка в окне. Тесты клиента на фейковом транспорте. `dotnet test`, `npm test`, `npm run lint`; `CHANGELOG.md` обоих проектов
