# 04: Push по SignalR и догон при переподключении

**What to build:** Сервер рассылает изменения подключённым клиентам пользователя пакетами раз в 100 мс. Клиент применяет их, а после разрыва догоняет с курсора.

**Blocked by:** 01, 03

**Status:** resolved

- [x] Хаб `/api/sync`, группа `user:{id}`; JWT из query `access_token` только для пути хаба
- [x] `IChangeNotifier`: пометка «грязного» пользователя после фиксации; диспетчер раз в 100 мс читает журнал из БД после последнего отправленного `seq` и рассылает сообщение в формате догона; медленному клиенту — `resync`
- [x] Подключение и отключение расширения рассылается как `resync`
- [x] Прокси Vite: `ws: true` в правиле `^/api`
- [x] Клиент (`@microsoft/signalr`): подключение в `SyncEngine`, переподключение (в том числе после обновления токена), догон `GET /api/changes?since=N` после соединения, `resync` → полная загрузка с переналожением очереди
- [x] Вкладка «Журнал» перечитывает первую страницу при сдвиге курсора
- [x] Тесты сервера с `Microsoft.AspNetCore.SignalR.Client`: две «вкладки» одного пользователя, чужой пользователь ничего не получает, группировка в окне. Тесты клиента на фейковом транспорте. `dotnet test`, `npm test`, `npm run lint`; `CHANGELOG.md` обоих проектов

## Comments

- Сервер: `Sync/SyncHub.cs` (группа `user:{id}`), `IChangeNotifier` + `ChangeDispatcher` (окно открывается первым уведомлением, затем `SyncService.ReadChangesAsync` после последнего отправленного `seq`). Пометка — в `ChangesetService.ApplyAsync` сразу после коммита. Сообщение `changes` — формат догона плюс `fromSeq`, чтобы клиент видел разрыв.
- «Медленный клиент → resync»: отправка группе ждёт записи во все соединения, поэтому медленный клиент задерживает рассылку пользователя, наборы копятся, и при превышении `ResyncThreshold` уходит `resync`. Отдельного учёта отставания по соединению нет.
- Клиент: `signalrChannel.ts` (канал), `syncEngine.ts` → `SyncLink { resync, catchUp, kick, connect, dispose }`. `DataController.load` идёт через `link.resync()`: сначала отправка неотправленного, потом снимок, очередь переналагается (`DataStore.reset` её сохраняет). Догон при разрыве курсора в подтверждении — через 1 с, если push не сдвинул курсор.
- Открыто: вкладка, получившая `resync` из-за смены подключения расширения в другой вкладке, перечитывает данные, но не каталог расширений (регистрации расширений не меняются) — нужен отдельный сигнал или перечитывание каталога по `resync`.
