# 19: Трекер: стартовая структура и Заметки

**What to build:** Первый рабочий сценарий Трекера: при первом входе клиентская логика создаёт стартовую структуру («Задачи» с «Текущие задачи» и «Завершённые задачи», «Заметки»), и пользователь ведёт заметки и группы заметок с вложенностью, статусом, приоритетом и внешней ссылкой.

**Blocked by:** 13 (Действия, хуки и диалог параметров), 16 (Цветовые правила)

**Status:** resolved

- [ ] Манифест Трекера дополнен: свойства «Заметки» (комментарий, приоритет, статус, внешняя ссылка), перечисления, действия, цветовые правила (средний приоритет — оранжевый, высокий — красный, статус «Завершена» — зелёный)
- [ ] При первом входе, если корней нет, логика модуля создаёт стартовую структуру одним набором изменений; при повторном входе дублей нет
- [ ] Действия «Создать заметку» и «Создать группу заметок» (с вложенностью групп) запрашивают название и создают объект
- [ ] Имя заметки вычисляется: «[Статус] Имя», если статус задан
- [ ] Действие «Перейти по внешней ссылке» открывает ссылку в новой вкладке браузера и доступно только при заданной ссылке
- [ ] Заметки каждого пользователя изолированы
- [ ] Тесты `DataController` на поддельном API (стартовая структура, повторный вход, создание, имя) и тесты UI проходят
- [ ] Запись в `CHANGELOG.md` клиента

Реализовано на ветке `integration/nimrata-pilot` (тикет 19), код-ревью пройдено, замечания исправлены. Серверные интеграционные тесты (Testcontainers) не выполнялись из-за недоступного Docker — прогнать `DOCKER_API_VERSION=1.43 dotnet test Nimrata.Core.slnx` при рабочем Docker.
