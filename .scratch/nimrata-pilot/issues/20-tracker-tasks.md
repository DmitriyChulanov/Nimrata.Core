# 20: Трекер: Задачи

**What to build:** Пользователь планирует задачи по дням: действие «Создать задачу» на выбранную дату (по умолчанию сегодня) создаёт нужные узлы года, месяца и дня и кладёт задачу в день, при желании в категорию. Задача имеет приоритет, время, статус, комментарий, внешнюю и внутреннюю ссылки; дата определяется днём-родителем.

**Blocked by:** 15 (Ссылочные свойства), 19 (Трекер: структура и Заметки)

**Status:** ready-for-agent

- [ ] Манифест дополнен типами Задача, Год, Месяц, День, День-выходной (определяется по дню недели), Категория; свойства задачи: комментарий, приоритет, время, «уведомить за (мин)», статус, внешняя ссылка, ссылка на внутренний объект, вид повтора, идентификатор повтора (скрытое)
- [ ] Действие «Создать задачу»: параметры название, дата (по умолчанию сегодня), необязательная категория (выбор существующей или ввод нового названия); логика находит или создаёт узлы месяца и дня внутри «Текущих задач»
- [ ] Категории вкладываются друг в друга внутри дня; повторное использование названия находит существующую категорию, а не создаёт дубль
- [ ] Имена вычисляются: месяц «MMMM, yyyy», день «dd.MM.yyyy, dddd», задача «HH:mm — Имя» при наличии времени
- [ ] Дата задачи нигде не хранится, а выводится из родителя-дня
- [ ] Дни сортируются по дате, задачи дня — по времени; цветовые правила для приоритета задач
- [ ] Действия «Перейти по внешней ссылке» и «Перейти по внутренней ссылке» работают
- [ ] Тесты `DataController` на поддельном API (узлы по требованию, категории, имена, выходной день) и тесты UI проходят
- [ ] Запись в `CHANGELOG.md` клиента
