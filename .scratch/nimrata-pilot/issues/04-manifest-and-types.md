# 04: Манифест и типы

**What to build:** Формат манифеста модуля и его путь до клиента: JSON-файл описывает типы, свойства, перечисления, допустимые дочерние типы, действия и цветовые правила; сервер при старте загружает его в таблицу типов, клиент получает типы по API. Первая версия манифеста Трекера содержит корневые группы, «Заметку» и «Группу заметок».

**Blocked by:** 03 (Вход и первый администратор)

**Status:** ready-for-agent

- [ ] Формат манифеста описан и проверяется схемой: идентификатор и версия модуля, типы, свойства (восемь видов), перечисления внутри свойств, абстрактность и запечатанность, допустимые дочерние типы, `hiddenInTree`, `automation`, действия с `placements` и параметрами, цветовые правила
- [ ] Манифест Трекера v0 лежит в клиентской части рядом с модулем; сервер читает тот же файл при старте (подключён в сборку сервера как контент)
- [ ] При старте типы вставляются или обновляются в таблице типов по версии манифеста; невалидный манифест останавливает старт с понятной ошибкой
- [ ] Эндпоинт возвращает типы авторизованному пользователю
- [ ] Клиент после входа загружает типы и хранит их в платформе для дальнейшего использования
- [ ] Интеграционные тесты (загрузка, повторный старт без дублей, обновление версии, невалидный манифест, доступ без токена) и клиентские тесты проходят
- [ ] Запись в `CHANGELOG.md` сервера и клиента
