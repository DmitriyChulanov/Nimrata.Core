# 03: Вход и первый администратор

**What to build:** Пользователь входит по e-mail и паролю и остаётся в системе между обновлениями страницы. Первый администратор создаётся при первом запуске из настроек развёртывания. Access-токен JWT (15 минут) хранится только в памяти вкладки, refresh-токен (около 30 дней) лежит в HttpOnly-cookie и обновляет access. Выход отзывает refresh на сервере.

**Blocked by:** 01 (Каркас сервера), 02 (Каркас клиента)

**Status:** resolved

- [ ] Таблицы пользователей и refresh-токенов в миграциях; пароли хешируются через `PasswordHasher`; минимальная длина пароля 8 символов
- [ ] При первом запуске создаётся администратор из настроек (user-secrets или переменные окружения); при повторном запуске дубль не создаётся
- [ ] Эндпоинты входа, обновления access по refresh и выхода; JwtBearer защищает остальное API; отключённый пользователь войти не может
- [ ] Refresh в HttpOnly-cookie с `SameSite=Strict`; при выходе токен отзывается и больше не принимается
- [ ] Клиент: экран входа, access только в памяти, при 401 один раз пробует обновить токен и повторяет запрос, после обновления страницы сессия восстанавливается через refresh
- [ ] Интеграционные тесты HTTP API (вход, неверный пароль, refresh, выход, отключённый пользователь) и тесты клиента проходят
- [ ] Запись в `CHANGELOG.md` сервера и клиента

Реализовано на ветке `integration/nimrata-pilot` (тикет 03), код-ревью пройдено, замечания исправлены. Серверные интеграционные тесты (Testcontainers) не выполнялись из-за недоступного Docker — прогнать `DOCKER_API_VERSION=1.43 dotnet test Nimrata.Core.slnx` при рабочем Docker.
