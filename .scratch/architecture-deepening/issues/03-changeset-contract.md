# 03: Контрактные сценарии Набора изменений для `fakeApi` и сервера

**What to build:** Один набор сценариев проверяет правила Набора изменений и в `fakeApi`, и на реальном сервере, чтобы клиентский тест не проходил там, где сервер откажет.

**Blocked by:** —

**Status:** resolved

- [x] Формат сценария: языконезависимый JSON (начальное состояние типов и Объектов, Набор изменений, ожидаемый признак успеха и код ошибки там, где он есть); общая папка сценариев, доступная клиентским и серверным тестам
- [x] Сценарии: допустимый родитель (`EnsureParentAllowsChild`), singleton (`EnsureSingletonAsync`), отключённое расширение (`extension_disabled`, `EnsureEnabled`), проверка значения (вид свойства, ссылка, `targetTypes`; `ValidateValueAsync`), проверка «было» (ADR 0001)
- [x] Vitest: раннер сценариев против `fakeApi`; xUnit: раннер против реального сервера (Testcontainers)
- [x] Сравнение по успеху и коду ошибки, не по тексту
- [x] Расхождения устранены в `fakeApi` (`PLATFORM_TYPES` сверен с миграциями `0023`, `0024`); если сценарий требует правила, которого нет в `fakeApi`, оно добавляется туда
- [x] Если сценарии покажут, что правила `ChangesetService` нельзя проверить без SQL, вынос в чистый module оформить отдельным тикетом, а не делать здесь
- [x] `dotnet test Nimrata.Core.slnx`, `npm test`, `npm run lint`; записи в `CHANGELOG.md` клиента и сервера

## Answer

Построено: `contracts/changeset/` (`types.json`, пять файлов сценариев — 62 сценария, `README.md` с форматом); клиентский раннер `fakeApi.contract.test.ts` (Vitest, `import.meta.glob`) и серверный `ChangesetContractTests` (xUnit + Testcontainers, сценарии копируются в вывод через csproj). Сравнение по успеху, коду ошибки и признаку конфликта (HTTP 409), не по тексту. Все 62 сценария сначала прошли на сервере, затем `fakeApi` приведён к ним.

Расхождения, найденные в `fakeApi` и устранённые: не было проверок значения (вид, enum, ссылка, `targetTypes`, неизвестное свойство), «было» для свойств, `parent` и `order`, неизвестного типа, занятого идентификатора, несуществующего родителя, родителя отключённого расширения, цикла при перемещении, singleton при перемещении, «объект не найден», удаления с потомками; в `PLATFORM_TYPES` не было `CustomCommand` (миграция `0023`). Из-за строгости `fakeApi` дополнены фикстуры 7 существующих тестов (объявлены свойства; в `tasks.test.ts` ссылка теперь повисает после удаления цели, а не указывает на несуществующий id). Проверка ссылки в `fakeApi` не требует формата GUID (в тестах id короткие).

Проверено: `npm test` (692), `npm run lint`, `tsc -b`, `dotnet test Nimrata.Core.slnx` (258) — зелёные, Docker был доступен.

Не входит в контракт: `delete`, `abstract`-типы, чужие объекты (владение), порядок проверок при нескольких ошибках сразу. Правила `ChangesetService` проверены через HTTP без выноса из SQL; необходимости в отдельном тикете сценарии не показали.
