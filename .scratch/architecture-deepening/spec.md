# Спецификация: углубление модулей клиента и контракт Набора изменений

Термины — в `GLOSSARY.md` (Название объекта, Действие, Команда, Набор изменений, Подключение расширения). Решения ADR 0001, 0003, 0004 не меняются. Источник — обзор архитектуры 2026-10-28 (отчёт в временной папке, не в репозитории).

## Цель

Свернуть дубли и размазанные правила в глубокие модули с узким interface, чтобы правило менялось в одном месте и тестировалось без `createFakeApi`.

## Решения

- **Название объекта.** Одно правило: свойство `name`, иначе название типа, иначе идентификатор типа. Копии в `Tree`, `ReferenceEditor`, `ActionDialog`, `DataController.objectLabel`, `JournalTab` заменяются одним вызовом. Свойство `title` в подписи больше не участвует. Диалог Действий для несуществующего Объекта по-прежнему показывает id (на месте вызова).
- **`objectQueries`.** Module платформы с запросами к дереву Объектов: Название объекта и обход родителей (`ancestors`). Принимает узкий `ObjectReader` (`getObject`, `getType`), в тестах заменяется литералом на `Map`. Расширения берут его через `@platform`. Серверный `IsAncestorAsync` не трогаем.
- **Реестр Действий и Команд.** `createActionRegistry({ reader, execute })` забирает `registerAction`, `registerCommand`, `findAction`, `actionParameters`, `getGroupActions`, `run*`, `missingRequired`. `DataController` делегирует реестру, его interface и вызывающие не меняются (принятое отличие: добавлен `groupLaunch`, убран `getGroupActionParameters`); сужение (`data.actions.*`) — отдельный шаг, если понадобится. Одиночный случай идёт через групповой путь. Правило «нет общих значений параметров» живёт только в реестре; `useActionLauncher` получает готовый результат.
- **Контракт Набора изменений.** Языконезависимые JSON-сценарии (родитель, singleton, `extension_disabled`, значение, «было») прогоняются против `fakeApi` (Vitest) и реального сервера (xUnit + Testcontainers). Сравнение по признаку успеха и коду ошибки, не по тексту. Расхождения чиним в `fakeApi`. Вынос правил из SQL в чистый module — только если сценарии покажут необходимость.
- **Подключение расширений.** Module без React вместо трёх копий цикла «синхронизировать регистрации → загрузить → проверить статус → запустить». Сброс выделения передаётся callback'ом, `ensureStart.reload` использует тот же цикл. `ExtensionsProvider` остаётся тонкой обёрткой над состоянием.
- **Модель дерева.** Чистый `treeModel` (видимые строки, раскрытие предков) для `Tree`, `ReferenceEditor` и `siblingsOf`. Мост `revealBridge`, `seq`-счётчик и скролл остаются. Порядок обхода `clipboard.ts` сверяется с видимым характеризующим тестом; выравниваем только при реальном расхождении, `hiddenInTree` не меняем.

## Вне плана

Общий скелет регистрации расширений (откладываем до третьего расширения), жесты и виртуализация `Tree`, сортировки `categoryTemplates`, `quickAccess`, `ActionDialog`, `PropertyGrid`, вынос правил Набора изменений из SQL.
