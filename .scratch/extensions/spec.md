# Спецификация: расширения и Редактор расширений

Термины — в `GLOSSARY.md` (Расширение, Подключение расширения, Редактор расширений, Трекер задач, Трекер заметок). Решения — в `docs/adr/0003-extension-connection-and-server-side-hiding.md`.

## Цель

Модуль «Трекер» разделяется на два независимых расширения, `tasks` («Трекер задач») и `notes` («Трекер заметок»). Пользователь сам подключает и отключает их в Редакторе расширений; данные отключённого расширения скрываются, но не удаляются. В будущем — пользовательские расширения (вне этого плана).

## Решения

- «Расширение» заменяет «Модуль» везде: глоссарий, интерфейс, код (`module` → `extension`, `types.module_id` → `extension_id`, каталог `src/modules/` → `src/extensions/`, алиас `@tracker` → `@tasks` и `@notes`).
- `tasks` и `notes` независимы. В `notes`: `NotesRoot`, `NoteGroup`, `Note`, `QuickAccessEntry`. В `tasks`: остальное, включая `SelectTodayMechanism`. Общие хелперы (`safeUrl`, переход по внутренней ссылке) уходят в платформу.
- Платформа (всегда доступна, не расширения): Журнал, Автоматизация, Пользователи, Тема.
- Подключение — серверная таблица «пользователь × расширение × включено», удаляется вместе с пользователем. Нет записи — действует `defaultEnabled` из манифеста (для обоих расширений `true`). Каждый пользователь управляет только своими подключениями.
- Метаданные расширения в манифесте: название, описание, иконка из реестра иконок, `defaultEnabled`. API: `GET /api/extensions` (каталог с состоянием пользователя) и `PUT /api/extensions/{id}/connection`.
- Скрытие делает сервер по расширению типа объекта (типы платформы видны всегда). `ManifestValidator` запрещает вложенность типов разных расширений. Запись (создание, изменение, перемещение, удаление) в объекты отключённого расширения отклоняется; ссылки в свойствах остаются данными, клиент видит их как ссылки на отсутствующий объект.
- Журнал фильтруется по расширению типа записи: в `changeset_entries` добавляется `type_id` (бэкфилл в миграции с обходом триггера неизменяемости: живые объекты — из `objects`, удалённые — из записи `create`/`snapshot`; неопределённый тип — запись видна всегда).
- Автосоздаваемые типы помечаются `singleton` в манифесте (`TasksRoot`, `CurrentTasksRoot`, `CompletedTasksRoot`, `NotesRoot`, `SelectTodayMechanism`); сервер отклоняет второй объект такого типа у того же родителя и владельца. `ensureStart` у каждого расширения идемпотентный: перед созданием перезагружает данные, при отказе по `singleton` считает «уже есть».
- Клиент: у расширения дескриптор (`register(data, options)` возвращает отписку, `ensureStart`, необязательные компоненты-привязки). `App` перебирает подключённые расширения и не знает о конкретных. Переключение без перезагрузки страницы: перезагрузка данных, очистка Undo/Redo, сброс выделения и вкладок на недоступные объекты. Пока расширение отключено, хуки, действия, повторы и уведомления не работают; при подключении `ensureRepeats` достраивает пропущенное.
- Миграция существующей БД: SQL-миграция переименовывает владельца типов (`tracker` → `tasks`, типы заметок → `notes`), идентификаторы типов и объектов не меняются. Версии новых манифестов выше 11, иначе `ManifestLoader` их не применит. Миграция выполняется до загрузки манифестов.
- Редактор расширений: вкладка с одной копией (`tabRegistry`), пункт «Вид → Расширения», карточки с названием, иконкой, описанием и переключателем; подтверждения нет, под переключателем текст «Данные скрываются и вернутся при повторном подключении».
- Вне плана: пользовательские расширения (песочница, загрузка и хранение чужого кода, редактор кода). Закладывается только форма клиентского дескриптора.

## Нарезка

См. `issues/01`–`05`: каждый тикет самостоятельный, тесты зелёные. Порядок: переименование → разделение → сервер → живое переключение на клиенте → вкладка редактора.
